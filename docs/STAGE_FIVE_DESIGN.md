# 阶段五：失败恢复、结果检查与终态

日期：2026-10-16。沿用 Python/FastAPI 单体架构和现有审批执行器。

## 恢复策略与预算

- 模型 HTTP 408/409/429/500/502/503/504、请求超时及普通传输错误沿用有限指数退避。401/400 等不可恢复 HTTP 错误直接结束；UnsupportedProtocol/LocalProtocolError 分类为 model_transport_configuration_error，不重试。日志只记录安全错误码。
- 无效 JSON、响应结构、空响应、未完整响应、过多工具或重复调用 ID 允许模型有限修正。无效批次整体不执行，反馈只包含校验码，不把非法 assistant/tool 结构送回供应商。修正使用下一轮，默认全运行最多 2 次；最后一轮仍保留收尾，硬输出限制直接失败。
- 工具参数错误和执行错误作为结构化结果反馈，模型可以改变参数、计划和动作。执行器不自动重放工具。相同工具和规范化参数连续失败默认 3 次即停止，计划/记忆更新不能重置该计数；正常工作工具成功后清零。
- 新增 max_tool_calls=64，非法调用、被阻止的调用以及检查使用的 shell 调用同样计数。模型修正、请求重试和检查均使用原任务的轮数、模型调用和总时长预算，不另开预算。文件检查受最多 20 个配置项、检查尝试次数、单文件大小和总时长限制。

max_retries 控制每次模型请求的临时错误退避；max_model_repairs 控制整个任务的格式修正次数；max_verification_attempts 默认 2 次，包括初次检查。所有配置均存入本次运行快照。

## 不确定副作用与拒绝

file_access_error、tool_timeout、tool_execution_error 可能发生在操作已有副作用之后。失败写入标记对应实际路径不确定，后续写入须先由 read_file 成功读取该文件；既有哈希冲突检查继续生效。只更新记忆或声称核对过不能解除限制。若文件不存在、读取失败或结果无法确定，应在报告中说明，不能直接重放。

shell 失败、超时或启动/控制错误标记副作用不确定；相同命令的普通工具重调被阻止，模型可选择其他经审批动作或报告不确定。此防重放使用参数等值判断，不是语义分析、沙箱或命令黑名单。新命令仍有可能重复业务副作用，必须由用户核对审批。

被用户明确拒绝的相同命令在本次运行中不再请求审批，包括配置检查；返回 approval_previously_rejected，不进入临时错误重试。新运行不继承旧批准或旧拒绝。

配置的 shell 检查是用户指定的可重复检查：前一次失败后，模型再次给出最终答复才会触发下一次检查尝试。检查命令即使前次失败也可重新请求批准，但始终产生新调用 ID 和新审批 ID，不复用授权，不暗中执行。检查命令应避免业务写入副作用；其失败的不确定性仍在最终报告中保留。模型普通命令没有这一检查重调路径。

## 配置检查与修正

checks 只能从本机配置加载，Web 请求和模型不能自行设置或改写验收标准；每次运行冻结检查列表。两类检查：

1. file_contains：id、type、工作目录内相对 path、非空 text。使用与文件工具相同的路径解析、链接边界、UTF-8 和体积限制，记录路径、字节数、原始文件 SHA256 与匹配结果。
2. shell：id、type、command、timeout_seconds。通过现有 run_command 执行器和 Web 审批代理执行，退出码 0 且未超时才通过；输出仍有上限。CLI 无审批代理时不能执行 shell 检查，返回失败证据，不降级为自动执行。

模型提出最终答复后执行全部配置检查。失败时，将实际证据反馈给模型；它可以在剩余预算内修正文件或计划并重新提交答复。超过检查尝试次数或最后一轮仍失败，记为 verification_failed。检查过程中可以取消，shell 仍有命令时限、总时限和 Windows Job 进程树清理。中断检查记为 interrupted/未通过，保留部分证据，不误报成功。

每次检查的开始、结果、整组通过情况和尝试次数写入同一事件流。最新证据固定进入模型上下文，即使旧交互被裁剪也不丢失；过大的检查上下文仍服从输入预算。此前尝试证据保留在事件中，最终报告显示最新尝试。

## 终态与报告

| 状态 | 含义 |
| --- | --- |
| completed | 非空配置检查全部实际通过，仅代表这些检查通过 |
| unverified | 模型结束但没有配置检查；模型自检和计划完成不能改变此状态 |
| verification_failed | 配置检查未通过且修正机会耗尽 |
| failed | 不可恢复请求错误、重复工具失败或执行器失败 |
| cancelled | 用户/嵌入应用取消，所启动进程按现有约束完成清理 |
| budget_exceeded | 时间、轮数、模型调用、工具调用或上下文预算耗尽 |
| interrupted | 没有终态记录且不再属于当前活动运行；只展示，不续跑 |

取消或预算耗尽优先保留其真实原因，不因此前检查失败而覆盖；进程树终止未确认仍强制 failed，阻止后续派发和新任务。CLI inspect 对无终态记录检查 owner_pid 的存活提示，存活时显示 running，否则 interrupted；PID 存活不能证明是原任务，旧记录也可能没有 owner_pid，不据此续跑。Windows 使用只读 OpenProcess/GetExitCodeProcess，避免用信号探测。

result.json 增加 operations、artifacts、checks、verification_attempts、unfinished_steps、unresolved 和 completion_scope。模型答案与执行器证据分开保存；执行中断的操作保留结果未知标识。文件产物清单来自成功写入证据，shell 任意生成的文件不自动遍历发现，配置文件检查可提供其哈希证据。

Web 显示正在检查、指定检查通过和检查失败，最终答复下面可展开检查证据、操作、产物及未完成事项，始终按文本安全渲染。CLI 对 completed/unverified 返回 0，对 verification_failed/failed/budget_exceeded 返回 1，取消返回 130。

## 限制

仅提供两类明确检查，不声称通用语义验收；检查证明的是执行当时的观察，不防恶意外部并发修改。检查命令输出可能包含敏感资料，沿用本地记录与密钥脱敏规则。结果报告不撤销已发生副作用，不支持事务回滚、自动重放或断点续跑。阶段六端到端整体验收仍需另行进行。
