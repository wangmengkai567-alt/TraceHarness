# 问答轮数耗尽修复

日期：2026-10-15。

## 原因与证据

用户问题“agent是什么？”的运行 `1e339d6915f14fe784e2135f99ecdf2b`，使用默认 max_turns=8。模型前七轮更新计划、列目录并读取多个项目文档与代码，第八轮仅调用 update_plan 和 update_memory。虽然模型将步骤标为 completed、在记忆里写“已给出最终回答”，实际上没有发送不带工具调用的最终答复。运行器达到硬上限，正确记录 budget_exceeded / turn_limit，但没有主动引导收尾。

两项诱因：系统提示将所有任务定位为 local file task agent，导致通用问答过度查文件；模型没有每轮轮数提醒，执行器也没有在配置轮数内预留答复机会。页面直接显示内部错误码，没有解释轮数预算。

## 修改

- 通用知识问答优先直接回答；用户询问项目或需要文件证据时才查工作目录。文件任务仍须先建立计划，任务内记忆继续保留事实/推测与来源。
- 每轮提供当前轮数/上限与及时作答提醒。最后一轮在原 max_turns 预算内专用于最终答复，不提供工具；若适配器仍返回工具调用，执行器拒绝派发并按预算终止。
- 不提高默认轮数、不增加隐含额外请求；模型调用数、重试、总时长、取消和输入输出限制继续生效。若剩余预算不足或供应商失败，仍可能明确失败，不承诺一定得到答案。
- 工具列表为空时，兼容适配器省略 tools 与 tool_choice 参数，避免供应商拒绝空数组。历史工具反馈与当前计划/记忆仍进入收尾上下文。
- 元数据记录 final_response_policy=reserve_last_turn。页面区分旧记录与新策略，展示已用轮数/上限和可读的停止原因。历史失败结果保留，不追改为成功。

`max_turns=1` 表示仅允许一次直接答复，不执行工具；需要工具反馈的任务应至少配置两轮。收尾可能如实报告未完成事项，正常 unverified 终态不表示通用验证通过。

## 验证

- 原有 51 项测试，加 7 项回归测试：最后一轮使用工具反馈作答、违规调用不落盘、完成状态不能替代答案、收尾请求重试不重放写入、调用数预算不扩张、收尾可取消、空工具请求协议。
- `node tests/test_web_ui.js`：直接执行实际前端脚本，验证历史错误解释、8/8 轮次、策略区别、最终答案及事件去重。
- 真实模型通过进程内 Web API 复测，配置仍为默认 8 轮、1024 completion tokens、30 秒请求时限、120 秒总时限。
- 同一句通用问题运行 `2212eabdc2574735a0b6de0127f76471`：1 轮、无工具调用、返回答案。
- 历史前七轮安全操作重放 + 一次真实模型收尾，运行 `44b7e103357b4a759f5d61098f4db331`：8 轮内得到答案，没有额外工具调用。此场景明确包含历史重放，不算全程真实模型执行。
- 结果见 `turn-limit-live.json`，测试输出见 `turn-limit-tests.txt`。
